# 设置页

插件在宿主里的设置页。用户在这里选搜索引擎、配 Key、切模式、查额度。这是插件跟宿主之间唯一的用户可见界面。

## Sub-features

- `settings-open` 从插件面板进到「搜索与抓取设置」。
- `settings-modes` 切搜索模式和抓取模式，卡片高亮跟着变，参数区跟着换。
- `settings-save` 保存后状态栏出现「设置已保存。」，未保存横幅消失。
- `settings-engine` 引擎列表列出 9 个引擎，各自带角色标签。
- `settings-quota` 刷新额度后各引擎卡片的用量行更新。
- `settings-verify` 配了 Key 的引擎可以点「验证」，状态栏回报返回条数和耗时。

## How to get to it (user POV)

- 点左下侧栏的「插件」按钮开插件面板。
- 在插件面板的「全局插件」区点「网页搜索路由器」。
- 或从账号菜单进「设置」，选「内置插件」，找到「网页搜索路由器」再点。

## Driving it with ego

Preconditions:

- 隔离 web 实例已起，Doctor 通过。
- 实例所在 profile 装的是本仓库当前代码。
- 首页的「预览版说明」和「开始使用」两个弹窗都关掉了，否则账号菜单点不动。

- **进设置页。** 打开实例的带 token URL，等标题变成 `DeepSeek Harness`。关掉两个弹窗后，用页内点击开账号菜单：

  ```js
  await page.evaluate(() => {
    document.querySelector("button[aria-label='账号菜单']").click();
  });
  ```

  再点菜单里的「设置」，对话框弹出后选左侧「内置插件」，等状态从「正在读取插件…」变成插件列表。往「全局插件」区找到按钮「网页搜索路由器」并点它。这个按钮的 aria-label 是「查看 网页搜索路由器」，按文本匹配有时对不上，按 aria-label 定位更稳。点开后再等几秒，设置页才加载完——刚点开时只有标题，页签还没渲染。期望：页面出现标题「搜索与抓取设置」，下面跟着一句「选好搜索和抓取用哪些引擎，把 Key 配好，再确认它们还能用。」

  另一条更省事的进法：不进设置对话框，直接点左下侧栏的「插件」按钮开插件面板，从「全局插件」区点「网页搜索路由器」。设置对话框开着的时候插件面板在底下，点不到。

- **看引擎列表。** 点「引擎」页签。期望：列出 Keenable、AnySearch、GitHub、Exa、Tavily、Firecrawl、知乎 / Zhihu、SiliconFlow、X / Twitter 九项，每项带角色标签（搜索 + 抓取 / 搜索 / 重排），页首显示「N / 9 已就绪」。

- **切搜索模式（动作前）。** 点「模式与模型」页签，截一张图。期望：搜索模式区有两张模式卡，标题分别是「质量」和「快速」，质量卡被选中（高亮）。

- **切到快速。** 点标题为「快速」的那张搜索模式卡。期望：这张卡高亮，下方出现「快速参数」区（首选引擎、失败回退家数），质量参数区消失。

- **保存。** 点页面顶部的「保存」按钮。期望：状态栏出现「设置已保存。」，未保存横幅「有未保存的改动」不再出现。

- **核保存真的落库（动作后）。** 点「总览」页签，看页首「就绪状态」文案。期望：文案里的模式跟刚才选的一致（快速模式显示「搜索已就绪（快速 · 匿名 N 家可用，配 Key 后更强）。」）。截一张图，这张跟动作前那张构成前后对比。

- **刷新额度。** 回「引擎」页签，点引擎列表标题右侧的「刷新额度」。期望：各引擎卡片的用量行有反馈——有额度接口的显示「剩余 <n>」，没有接口的显示「不支持」，查不到的显示「刷新失败」。keyless 下 Keenable 报「刷新失败」是预期的，额度要先跑一次搜索才有缓存。

- **留证据。** 每个动作前一张、动作后一张，存成 `<序号>-<步骤>.png`。保存前后的两张要能看出模式卡的高亮换了位置。

## Gotchas

- 设置页入口不在「内置插件」的插件列表里。「内置插件」只列内置工具包；本插件的设置页挂在 bundle 配置槽位上，入口是插件面板里的「网页搜索路由器」按钮。
- 首页的「开始使用」弹窗会挡住账号菜单，不关它点不动。
- 「账号菜单」按钮上面盖着一层 div，ego 的原生点击报 `<div> intercepts pointer events`，改用 `page.evaluate` 页内点击。
- 「设置」对话框的关闭按钮是文本「关闭」，没有 aria-label，按文本匹配。
- 设置对话框开着的时候插件面板在底下，点不到。先关对话框，或者直接从侧栏的「插件」按钮进插件面板。
- 设置页刚点开时要等几秒才加载完，只看到标题是正常的。
- 模式卡是 `<button>` 套两个 `<span>`（标题和说明）。文本匹配要落在 span 上，按钮上匹配不到。
- 按钮文本「快速」有两个，搜索模式一个、抓取模式一个。靠说明文字区分：搜索模式是「自动选择第一个引擎；失败时最多再试 N 家。」，抓取模式是「快速：直接抓整页，速度优先。」
- keyless 下「验证」按钮是 disabled 的，Keenable、AnySearch、GitHub 三张卡都标「未配置」。这是预期，不是故障。要验健康检查走 Doctor 里的 `/dsh-web-search/health`。
- 保存是写操作，会改 profile 配置。验收用的 profile 是一次性的，存完随实例一起删，不影响本机。
- 字体文件路由和凭据管理路由不是用户能碰到的面，不单列成功能。字体路由由 `lib/fonts-routes.js` 注册，管理路由的信任判定见 `lib/health.js` 的 `isTrustedRequest`。
- 桌面端的设置页跑在 `dsh-app://`，ego 拿不到它的鉴权 cookie。不验桌面端。
- 本轮未跑：带 Key 的「验证」按钮、SiliconFlow 的「拉取模型」、各付费引擎的额度显示。这几条需要真实 provider key，keyless 路径够不到。要跑走 keyed 路径。
