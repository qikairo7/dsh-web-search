# ADR-0014: 直连 HTTP 默认拦截私网地址

Status: Accepted. 决策于 2026-11-21 确定，先于实现；对应 #182（票内同时处理 #184 错误路径取消响应体）。

## 背景

- 直连 HTTP provider（`lib/providers/http.js`）此前只校验 URL 协议，不校验主机地址：传入回环、私有网段、链路本地或云元数据地址会原样请求并返回内容，重定向也只判断目标协议、不判断目标主机。
- 这是一条 SSRF 通道：构造的 URL 能从本机访问内网服务或云元数据接口（如 169.254.169.254），把不可信输入变成对内网的请求。
- `SAFETY.md`、`SAFETY.zh.md` 与 `docs/defensive-patterns.md` 原写「直连 HTTP 按设计可访问回环和私网」，与拦截需求冲突；维护者 2026-11-21 拍板改为默认拦截加环境变量逃生门。

## 决策

- 默认拦截回环、私有网段（10/8、172.16/12、192.168/16）、链路本地（169.254/16、fe80::/10）、唯一本地（fc00::/7）、云元数据段与 IPv4 映射地址，另含 0/8、100.64/10 及组播、保留段。不拦 198.18.0.0/15：Clash 等代理的 fake-ip 模式用它把公网域名映射到本地代理，拦了会误杀正常公网抓取（真机验收实测本机 DNS 即返回 198.18.0.x）。
- 首次请求和每次重定向都校验：重定向目标除判断协议，还要解析域名并检查解析结果，任一跳命中内网即拒绝，抛终止错误 `WEB_PRIVATE_URL`，不触发回退，避免把内网 URL 交给其他 provider。
- 防 DNS rebinding 取最低要求：先 `dns.lookup` 解析域名，解析结果命中内网即拒绝，再发起请求。
- 已知局限：Clash fake-ip 类环境下，公网域名被解析成代理网段（本机实测 example.com→198.18.0.200），基于域名的私网校验看不到真实目标，域名型防护不生效；直连的私网字面量仍被拦。
- 逃生门：启动环境设置 `DSH_WEB_HTTP_ALLOW_PRIVATE=1`（真值 1/true/yes/on）放行全部私网段（回环、私有、链路本地与云元数据 169.254.169.254），供本机调试；云环境开启会暴露实例元数据端点。该值只在 `lib/host.js` 读取，provider 不直接读进程环境。
- 防护落在 `lib/host.js`（地址判定与解析校验），provider 只调用；契约变更同步更新 SAFETY 双语与 `docs/defensive-patterns.md`。

## 放弃的替代方案

- 只在请求后再校验返回内容：请求已经发出，内网已被触达，太晚。
- 只在 provider 写死地址段、不做域名解析：域名指向内网时漏防（DNS rebinding）。
- 做成配置字段而非环境变量：要同时改 Config、`DEFAULT_SETTINGS` 与文档，且这是部署侧本机调试开关，环境变量更贴合。
- 把防护上移到 AutoFetchProvider 覆盖所有抓取 provider：其他 provider 是远端抓取，不构成本机 SSRF；按最小改动只护直连 HTTP。

## 后果

- 依赖直连 HTTP 抓本机或内网的用户需显式设置 `DSH_WEB_HTTP_ALLOW_PRIVATE=1`，否则被拒。
- `100.64.0.0/10` 不是 RFC1918 私网，但属 CGNAT 与虚拟内网（如 Tailscale）常用段，同样在拦截范围；需要时用逃生门放行。
- DNS 校验与真正连接之间存在 TOCTOU 窗口（解析后再 rebinding），issue 只要求解析后校验，按已知上限记录，不做连接钉扎。
- 公网抓取路径不变；403/429/5xx 与不支持 content-type 的错误码不变。
