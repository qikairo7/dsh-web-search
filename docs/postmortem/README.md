# 事故复盘（postmortem）

本目录是事故叙事层：一次事故一份记录，写清故事与证据。它属于 incident-scoped reference，只解释单次事故，不定义当前行为。

## 与错题本的分工

- 本目录记故事与证据：时间线、影响、根因、教训。一条教训在这里写清来龙去脉。
- 错题本（`REVIEW-LESSONS.md`，维护者本地文件）记规则：一行一条可执行规则，带 Seen 计数与证据。
- 本目录的每条教训必须回流错题本，先经 `REVIEW-LESSONS-inbox.md` 预记，再由复盘任务按正式格式入账。只写故事不入账，等于没复盘。

## 触发条件

出现下面任一情况，就写一份复盘：

- 事故造成用户可见影响，比如搜索或抓取报错、数据损坏、发布失败。
- 发版后回滚。
- 质量事件要 3 轮以上修复回环才收敛。

## 写作

写之前先加载 `zh-tech-writing`。正文用中文，代码、命令、标识符原样。一篇一个文件，文件名用 `<日期>-<短标题>.md`。

## 格式模板

```markdown
# <一句话标题>

## 时间线

- HH:MM <发生了什么>

## 影响

<受影响的功能、用户、数据，有无丢失，怎么发现>

## 根因

<直接原因与系统性原因，指到具体文件、提交或流程缺口>

## 教训 → 规则化

- <教训>
  - 回流：<对应错题本条目或守卫检查；经 REVIEW-LESSONS-inbox.md>
```
